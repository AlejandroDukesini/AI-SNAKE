IA-SNAKE - CAMBIOS REALIZADOS E INSTRUCCIONES DE EJECUCION
================================================================
Fecha: 2026-11-16 · Version 3.0.0 · Motor 1.0.0

1. QUE CAMBIO
-------------
El proyecto dejo de ser "Snake IA - Neuroevolucion" (algoritmo genetico sobre redes
neuronales) y paso a ser IA-SNAKE: un laboratorio donde cinco modelos resuelven el mismo
Snake con metodologias distintas. La neuroevolucion no correspondia a ninguna de ellas y su
motor estaba acoplado al modelo, asi que se reconstruyo desde cero.

  - La version anterior completa queda en la etiqueta git:  v2-neuroevolucion
  - Se retiraron del arbol: snake_neuroevolution.py, ai_server.py, storage.py,
    migrar_historial.py, benchmarks/, la interfaz anterior (src/), el modo borrador del
    navegador, la analitica/cookies, netlify.toml, vercel.json, .env.demo y los documentos
    de la neuroevolucion.
  - NO se tocaron tus datos locales: historial/, probando-ia/, mejores_ias.json, config.json.

2. RAMAS Y FLUJO (decision D1)
------------------------------
Una rama por pieza; cada una se fusiono en Beta solo con todas las pruebas pasando:
  nucleo -> arkis -> lerk -> bork -> clark -> laboratorio  ==>  Beta
Principal (produccion) NO se ha tocado: pasa de Beta a Principal tras tus pruebas.

3. QUE SE CONSTRUYO
-------------------
  Etapa 2 · Motor (ia_snake/nucleo/)
    - Tableros 4x4 (longitud inicial 1), 8x8 y 16x16 (longitud 3). El dificil es 16x16 (D0).
    - Tres sentidos: cuerpo (matriz + segmentos sincronizados), manzana, muros.
    - Recompensa configurable con 8 componentes registrados por separado.
    - Detector de ciclos y regla de 30 s en tiempo de juego (D2).
    - E0-E8 con C(E_n) = techo(n*N/8) y record historico por modelo y dificultad.
  Etapa 3 · Modelos individuales
    - ARKIS: Random Forest con tus etiquetas, validacion GroupKFold por episodio, metricas
      completas, simetrias exactas, recopilacion activa sin etiquetar.
    - LERK: reglas con excepciones; induccion (cobertura secuencial), experiencia, correccion
      Ripple-Down Rules, generalizacion, validacion y conflictos. Explica cada decision.
    - BORK: Q-Learning tabular con estado compacto, curva por episodio y medicion de aliasing.
  Etapa 4 · CLARK
    - Hibrido con tres componentes propios (RF + reglas + tabla Q), integracion documentada
      (vetos -> conocimiento del usuario -> pesos). Empieza sin entrenar (D4).
  Etapa 6 (parcial) · Laboratorio
    - Servidor FastAPI (ia_snake/servidor/) e interfaz React: Panel, Simulador (observar,
      demostrar, jugar, corregir), Entrenamiento (un panel por modelo), Evolucion,
      Comparacion y Documentacion.
    - Persistencia por modelo: versiones inmutables con SHA-256, recuperacion ante errores,
      exportar/importar .zip, copias de seguridad, SQLite de episodios. Sin pickle (skops).
  Pendiente
    - MABU (Etapa 5): presentar su arquitectura para tu aprobacion; preentrenamiento al final.
    - Etapa 7: validacion final contigo (tus pruebas) y paso a Principal.

4. COMO EJECUTAR
----------------
  Requisitos: Python 3.10+ y Node.js 18+

  pip install -r requirements.txt
  pip install -r requirements-dev.txt      (solo para las pruebas)
  npm install

  npm run dev:all    -> servidor en :8000 + interfaz en http://localhost:5173
  npm run build
  npm start          -> produccion: un solo proceso sirve web y API en :8000

  python -m pytest                     -> 118 pruebas
  python scripts/lineas_base.py        -> azar y voraz en las tres dificultades
  python scripts/medir_modelos.py      -> entrena cada modelo desde cero y lo evalua

  Tus modelos se guardan en laboratorio/<modelo>/ (no se sube a git).
  Para usar otra carpeta:  IA_SNAKE_DATOS=/ruta npm run dev:all

5. LIMITACIONES CONOCIDAS
-------------------------
  - La interfaz compila y el servidor se probo de extremo a extremo con peticiones reales,
    pero la interfaz no se reviso visualmente en un navegador: queda para tus pruebas.
  - Los modelos superan claramente al azar; frente a la regla voraz los resultados varian
    por modelo (ver docs/ia-snake/RESULTADOS.md). En 8x8 solo LERK alcanzo E8 (2 de 50
    partidas); 16x16 no se ha medido con entrenamiento completo.
  - Las cifras de RESULTADOS.md vienen de un solo entrenamiento por modelo (semilla 0).
  - El rendimiento de ARKIS depende de tus etiquetas; la cifra de RESULTADOS.md usa un
    profesor sintetico solo para verificar que el mecanismo aprende.
  - Entrenar en 16x16 es lento en Python puro (flood-fill por paso).
  - La comparacion y las evaluaciones bloquean un trabajo por modelo a la vez.
